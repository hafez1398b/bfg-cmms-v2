# نصب سازمانی سامانه BFG CMMS/EAM

این بسته برای سرور لینوکسی ۶۴ بیتی با Docker و افزونه Docker Compose آماده شده است. پایگاه داده داخل شبکه Docker قرار می‌گیرد و مستقیماً روی اینترنت منتشر نمی‌شود.

## پیش‌نیازها

- سرور لینوکسی به‌روز
- Docker Engine
- Docker Compose نسخه ۲
- حداقل ۴ گیگابایت حافظه برای برنامه و پایگاه داده
- فضای دیسک پایدار و برنامه پشتیبان‌گیری
- برای مدل محلی، حافظه بیشتر متناسب با مدل لازم است

## نصب سریع

```bash
tar -xzf bfg-cmms-company-installer.tar.gz
cd bfg-cmms-company-installer
chmod +x deploy/*.sh
./deploy/install.sh
```

نصب‌کننده به‌صورت خودکار این موارد را می‌سازد:

- رمز تصادفی پایگاه داده
- کلید امضای نشست‌ها
- رمز اولیه مدیر سیستم
- PostgreSQL 16
- ساختار کامل پایگاه داده
- مدیر سیستم «حافظ بایرامیان»
- اطلاعات تأییدشده بسپار ۱، فقط در پایگاه داده تازه

رمز اولیه مدیر فقط در پایان نصب نمایش داده می‌شود. فایل `.env` با سطح دسترسی محدود ساخته می‌شود و نباید در Git یا پیام‌رسان قرار گیرد.

## نشانی سامانه

```text
http://SERVER_IP:8080
```

برای بهره‌برداری واقعی، سامانه را پشت Reverse Proxy سازمان و گواهی HTTPS قرار دهید. پورت 8080 را فقط برای شبکه داخلی یا Proxy مجاز کنید.

## پشتیبان‌گیری

```bash
./deploy/backup.sh
```

خروجی رمزنگاری‌نشده پایگاه داده در پوشه `backups` قرار می‌گیرد. این پوشه باید روی فضای پشتیبان امن و ترجیحاً رمزنگاری‌شده کپی شود.

نمونه اجرای روزانه با Cron:

```cron
15 2 * * * cd /opt/bfg-cmms-company-installer && ./deploy/backup.sh >> /var/log/bfg-cmms-backup.log 2>&1
```

## بازیابی

```bash
./deploy/restore.sh backups/FILE.dump
```

بازیابی، پایگاه داده جاری را جایگزین می‌کند و به تأیید صریح نیاز دارد.

## به‌روزرسانی

فایل‌های نسخه جدید را جایگزین کنید و سپس:

```bash
./deploy/update.sh
```

این دستور پیش از ساخت نسخه جدید، پشتیبان تهیه می‌کند.

## فعال‌کردن مدل محلی

نمونه مدل کم‌حجم:

```bash
./deploy/enable-local-ai.sh qwen2.5:3b
```

پس از دریافت مدل، مقادیر اعلام‌شده توسط اسکریپت را در `.env` قرار دهید و برنامه را بازسازی کنید. مدل مناسب نهایی باید براساس حافظه سرور و کیفیت موردنیاز انتخاب شود.

## فعال‌کردن DeepSeek و Gemini

کلیدها را فقط روی سرور و در فایل `.env` قرار دهید:

```text
DEEPSEEK_API_KEY=...
GEMINI_API_KEY=...
```

سپس:

```bash
docker compose -f docker-compose.company.yml up -d --force-recreate app
```

Providerهای ابری در سیاست پایگاه داده به‌صورت پیش‌فرض غیرفعال‌اند. مدیر سیستم باید پس از بررسی محل پردازش داده، Provider و مجوز ارسال Context را از صفحه تنظیمات هوش مصنوعی فعال کند.

ترتیب بازیابی هوش مصنوعی:

```text
Provider تخصصی → DeepSeek → مدل محلی → خطای شفاف
```

## کنترل سلامت

```bash
curl -fsS http://127.0.0.1:8080/api/health
```

پاسخ آماده باید شامل این وضعیت باشد:

```json
{"status":"ready","database":true,"schemaReady":true}
```

مشاهده سرویس‌ها و گزارش‌ها:

```bash
docker compose -f docker-compose.company.yml ps
docker compose -f docker-compose.company.yml logs --tail=200 app
docker compose -f docker-compose.company.yml logs --tail=200 database
```

## ملاحظات امنیتی

- فایل `.env` را از سرور خارج نکنید.
- کاربران واردشده از Seed به‌صورت پیش‌فرض غیرفعال‌اند و رمز مشترک ندارند.
- حساب هر کاربر را مدیر با رمز مستقل فعال کند.
- کلیدهای Cloud را در Browser وارد نکنید.
- دسترسی SSH و Firewall را محدود کنید.
- HTTPS، نسخه پشتیبان خارج از سرور و مانیتورینگ دیسک الزامی است.
- پیش از حذف Neon، انتقال و شمارش رکوردها و حداقل یک Restore آزمایشی را تأیید کنید.
