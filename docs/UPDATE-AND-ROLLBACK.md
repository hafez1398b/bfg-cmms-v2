# انتشار به‌روزرسانی و بازگشت به نسخه قبل

این روش فقط روی خود سرور و با فایل‌های همین نسخه اجرا می‌شود. برنامه هیچ کد، SQL یا JavaScript را از آدرس خارجی دریافت یا اجرا نمی‌کند. ماژول جدید از رابط کاربری نصب نمی‌شود.

## انتشار ماژول

ماژول جدید فقط داخل یک نسخه نرم‌افزاری امضاشده منتشر می‌شود:

1. شناسه، نام، نسخه، مجوزها، حداقل نسخه Backend و حداقل نسخه کلاینت در `server/module-catalog.js` اضافه می‌شود. این فهرست در کد نسخه است، نه در یک آدرس قابل‌دانلود.
2. اگر جدول جدید لازم است، یک مهاجرت شماره‌دار و تکرارپذیر در `migrations/` اضافه می‌شود. نام فایل باید `NNN_name.sql` باشد.
3. پوسته همان مبدأ، در صورت نیاز، `BFGModules.register({ id, menuIds, render })` را صدا می‌زند. `scriptUrl`، `src` و `code` پذیرفته نمی‌شوند.
4. بسته ویندوز بعداً با Authenticode و بسته اندروید با امضای APK نسخه ۲ و ۳ امضا می‌شود. این مرحله هنوز نصب‌کننده نمی‌سازد.
5. `POST /api/modules` همیشه `405` و `MODULE_PUBLISH_REQUIRES_SIGNED_RELEASE` برمی‌گرداند. شناسه خارج از فهرست امضاشده هم فعال نمی‌شود.

فعال یا غیرفعال کردن ماژول موجود فقط برای نقش `admin` است و از `PATCH /api/modules/:id` با `rowVersion` انجام می‌شود. این کار کد جدید نصب نمی‌کند.

## قبل از مهاجرت

به‌روزرسانی پایگاه فقط بعد از یک پشتیبان محلی و تازه‌تر از ۲۴ ساعت اجرا می‌شود. مسیر پشتیبان باید فایل روی همین سرور باشد، نه URL.

```bash
mkdir -p backups/app
pg_dump --format=custom --file=backups/app/bfg-before-update.dump "$DATABASE_URL"
npm run update:apply -- backups/app/bfg-before-update.dump
```

`BACKUP_PATH` هم به‌جای آرگومان پذیرفته می‌شود. اگر فایل نباشد، کوچک باشد، کهنه باشد، یا آدرس شبکه باشد، هیچ مهاجرتی اجرا نمی‌شود.

اسکریپت `scripts/apply-update.js` این کارها را به ترتیب انجام می‌دهد:

1. پشتیبان را روی دیسک محلی بررسی و SHA-256 آن را حساب می‌کند.
2. جدول‌های دفتر مهاجرت را، اگر نباشند، می‌سازد.
3. وجود `audit_x` را بررسی می‌کند. بدون Audit مهاجرت شروع نمی‌شود.
4. مسیر و checksum پشتیبان را در `system_restore_points` با محدوده `application-update` ثبت می‌کند.
5. فقط فایل‌های `migrations/` همین نسخه را به ترتیب شماره اجرا می‌کند. فایل قبلاً اعمال‌شده با checksum یکسان دوباره اجرا نمی‌شود. checksum متفاوت متوقف می‌شود.
6. شروع به‌روزرسانی، نتیجه هر مهاجرت و پایان کار در `audit_x` ثبت می‌شود.

مهاجرت‌های `002` تا `012` تکرارپذیرند. `010` فقط جدول گفتگوی ورود هوشمند تجهیزات را اضافه می‌کند. `011` کلید مجوز قدیمی `tree` را به `equipment` منتقل می‌کند و مجوز ذخیره‌شده را حذف نمی‌کند. `012` جدول پیش‌نویس و تأیید یک‌بارمصرف سلن را اضافه می‌کند و بایت فایل را ذخیره نمی‌کند. اولین اجرای کنترل‌شده، مهاجرت‌های قبلاً اعمال‌شده را یک‌بار دیگر به‌صورت بی‌اثر اجرا و سپس در `schema_migrations` ثبت می‌کند. به همین دلیل پشتیبان قبل از این اجرا الزامی است.

## بازگشت کد به نسخه قبل

اگر مهاجرت هنوز اجرا نشده است:

1. برنامه را متوقف کنید.
2. بسته امضاشده نسخه قبل را دوباره نصب کنید، یا در سرور منبع همین مخزن را به commit نسخه قبل برگردانید.
3. هیچ اسکریپت بازگشتی را از اینترنت دانلود یا اجرا نکنید.
4. برنامه را با همان `DATABASE_URL` قبلی راه بیندازید و `GET /api/health` و `GET /api/runtime-config` را ببینید.

اگر مهاجرت اجرا شده است، برگرداندن فقط کد کافی نیست. اول پایگاه را از همان پشتیبانی که قبل از `update:apply` تأیید شده برگردانید، بعد کد نسخه قبل را اجرا کنید.

1. برنامه را متوقف کنید تا نوشتن جدید انجام نشود.
2. پایگاه مقصد را قطعی کنید. دستور زیر اشیای همان پایگاه را با نسخه پشتیبان عوض می‌کند و نباید روی پایگاه دیگری اجرا شود.

```bash
pg_restore --clean --if-exists --dbname="$DATABASE_URL" backups/app/bfg-before-update.dump
```

3. checksum فایل را با مقدار `system_restore_points.checksum` یا یادداشت Audit همان به‌روزرسانی مقایسه کنید. اگر فرق دارد، بازیابی را ادامه ندهید.
4. کد را به همان نسخه امضاشده قبل از به‌روزرسانی برگردانید. `schema_migrations` را دستی حذف نکنید؛ بازیابی پشتیبان، پایگاه و این جدول را با هم به حالت قبل برمی‌گرداند.
5. برنامه نسخه قبل را راه بیندازید. کلاینت قدیمی‌تر از `minClientVersion` صفحه به‌روزرسانی می‌بیند و داده محلی نمی‌سازد.

پشتیبان JSON تجهیزات (`npm run backup:equipment`) نقطه بازگشت همان دامنه است و جایگزین `pg_dump` کل برنامه نیست.

## کلاینت ناسازگار

Backend در `GET /api/runtime-config` نسخه برنامه، نسخه API و حداقل نسخه کلاینت را اعلام می‌کند. کلاینت نسخه خود را در `x-client-version` می‌فرستد. اگر نسخه نباشد یا از حداقل کمتر باشد، صفحه به‌روزرسانی نشان داده می‌شود و ورود، داده نمونه و حافظه عملیاتی ادامه پیدا نمی‌کند. آن صفحه دکمه دانلود کد ندارد و فقط همین صفحه را دوباره بارگذاری می‌کند.
