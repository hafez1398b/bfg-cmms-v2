# پاک‌سازی داده‌های پیش‌فرض تجهیزات

## تصمیم اجراشده

- فقط داده‌های نمونه و نمایشی قدیمی حذف می‌شوند.
- داده‌های واقعی یا Import‌شده بسپار ۱ حفظ می‌شوند.
- پس از Reset، ساختار Canonical تأییدشده دقیقاً یک‌بار بارگذاری می‌شود.
- در اجراهای بعدی Import تکرار نمی‌شود و اطلاعات ثبت‌شده کاربر حفظ خواهد شد.
- تجهیزات نمونه قدیمی دوباره ایجاد نمی‌شوند.

## محدوده پاک‌سازی

- تجهیزات اولیه `a5` تا `a10`
- تجهیزات نمونه کارخانه Memory Foam
- خودروها و تجهیزات متحرک نمونه
- ساختار نمونه پرس، زیرسیستم‌ها و تابلوهای برق
- Work Orderهای Demo و Work Orderهای وابسته به Assetهای حذف‌شده
- PM، درخواست تعمیر، کالیبراسیون، مجوز و جانمایی نقشه وابسته
- قطعات و اسناد انبار نمونه اولیه
- ارتباطات Asset در برنامه‌ها، پروژه‌ها و ابزارهای امانی

ساختار مکان، کاربران، تنظیمات، داده‌های دستی و Assetهایی که کاربر وارد کرده حذف نمی‌شوند.

## Browser/Demo Store

فایل زیر در انتهای Boot اجرا می‌شود و پاک‌سازی را به‌صورت idempotent انجام می‌دهد:

```text
public/data/equipment-demo-cleanup.js
```

گزارش آخرین اجرا در `DB.equipmentDemoCleanup` ذخیره می‌شود.

## PostgreSQL

برای حذف همان داده‌های نمونه از PostgreSQL:

```bash
npm run clean:demo-equipment
```

اسکریپت `scripts/clean-demo-equipment.js` تمام عملیات را در یک Transaction انجام می‌دهد. در صورت خطا، عملیات Rollback می‌شود.

## بارگذاری ساختار Canonical بسپار ۱

پس از صفرشدن ساختار، Browser Adapter فایل Canonical را فقط یک مرتبه بارگذاری می‌کند و سپس نشانگر `awaitingCanonicalStructure=false` مانع تکرار Import می‌شود. اجرای دستی مجدد در صورت نیاز ممکن است:

```js
importBespar1()
```

برای PostgreSQL، Import با فرمان صریح انجام می‌شود:

```bash
npm run seed:besepar1
```
