# ورود داده‌های کارخانه بسپار ۱

## منبع واحد داده

فایل `public/data/besepar1.seed.json` منبع Canonical این Import است و هم توسط نسخه Demo مرورگر و هم توسط PostgreSQL Seeder مصرف می‌شود. Importها idempotent هستند و داده‌های سایر کارخانه‌ها را حذف نمی‌کنند.

## ساختار سازمانی نهایی

```text
شرکت بسپار فوم غرب
├── دفتر مرکزی
└── کارخانجات
    ├── بسپار ۱
    ├── بسپار ۲
    ├── بسپار ۳
    ├── بسپار ۴
    ├── بسپار ۵
    └── بسپار ۶
```

زیر هر کارخانه دقیقاً ۱۰ دسته استاندارد قرار می‌گیرد و تجهیزات فقط زیر یکی از همین دسته‌ها ثبت می‌شوند.

## محتوای واردشده

- ۶ کارخانه: بسپار ۱ تا بسپار ۶
- ۶۰ گره دسته سازمانی؛ ۱۰ دسته استاندارد برای هر کارخانه
- ۱۰ تجهیز اصلی ثبت‌شده در بسپار ۱
- ۵ تجهیز جدید با کد موقت `TMP-*` و وضعیت `needs-coding`
- ۵ زیرتجهیز کانوایر B1P08-1 تا B1P08-5
- ۶۳ سابقه تعمیراتی تأییدشده تا سال ۱۴۰۴
- ۲۵ قلم قطعه یدکی و اتصال چندبه‌چند آن‌ها به تجهیزات
- ۳۵ برنامه PM دوره‌ای
- WO-1405-033 به‌عنوان دستورکار فعال و تأییدشده
- ۱۴ دستورکار پیشنهادی سال ۱۴۰۵ با وضعیت `pending-confirmation`
- ۶ تکنسین و تخصص‌های مربوطه

## سیاست کیفیت داده سال ۱۴۰۵

دستورکارهای WO-1405-034 تا WO-1405-048 به‌جز WO-1405-037 به‌عنوان رکورد مستقل ثبت شده‌اند. WO-1405-037 مطابق دستور، به‌جای Work Order تکی به PM ماهانه Recurring با مرجع `PM-M-005` تبدیل شده است.

برای رکوردهای پیشنهادی:

- `status = draft`
- `confirmation_status = pending-confirmation`
- `period_label` فقط ماه وقوع را نگه می‌دارد.
- `times.start/end = null`
- `provisional_fields` فیلدهای نیازمند تأیید را مشخص می‌کند.
- نام تعمیرکار پیشنهادی است و در `report/source_metadata` برچسب‌گذاری می‌شود.
- UI با هشدار نارنجی «نیاز به تأیید نهایی» این رکوردها را نمایش می‌دهد.

WO-1405-046 فاقد Asset اصلی است و B1P01 و B1P02 در جدول `work_order_assets` با رابطه `candidate` و `is_confirmed=false` ثبت می‌شوند.

## تجهیزات نیازمند کدگذاری

- `TMP-B1-ADM-WP` — پمپ آب ساختمان اداری
- `TMP-B1-POL-PIPE` — خط لوله پولیول انبار مواد
- `TMP-B1-ISO-PUMP` — پمپ ایزو انبار مواد
- `TMP-B1-ISO-MOTOR` — الکتروموتور انبار ایزو
- `TMP-B1-BLEND-PUMPS` — پمپ‌های بلندینگ پولیول

فیلد `assets.requires_coding=true` مانع اشتباه گرفتن کد موقت با کد رسمی می‌شود.

## اجرای PostgreSQL Import

```bash
npm install
npm run seed:besepar1
```

Seeder ابتدا migration شماره ۰۰۲ را به‌صورت idempotent اعمال و سپس تمام داده‌ها را در یک Transaction وارد می‌کند. در صورت خطا، Data Transaction کامل Rollback می‌شود.

## تغییرات مدل داده

Migration `migrations/002_bespar1_master_data.sql` موارد زیر را اضافه می‌کند:

- `asset_categories`: رابطه یک‌به‌چند کارخانه و دسته سازمانی
- `assets.category_id` و `assets.requires_coding`
- فیلدهای Data Quality در `work_orders`
- `asset_spare_parts`: اتصال تجهیزات و قطعات یدکی
- `work_order_assets`: Asset اصلی، مرتبط و Candidate
- metadata و وضعیت Recurring برای PM

## نکته محیط فعلی

اگر PostgreSQL تعریف‌شده در `DATABASE_URL` در دسترس نباشد، Seeder دیتابیس اجرا نمی‌شود؛ با این حال Adapter مرورگر داده‌ها را در Demo Store وارد می‌کند و تمام اطلاعات در پیش‌نمایش قابل مشاهده است.
